# 모둠 배정 & 생기부 기록 관리

학생 명단을 등록하고 랜덤 또는 교사 직접 배정으로 모둠을 구성한 뒤, 모둠 활동 기록과 학생 개인별 기록(생활기록부 특기사항 작성용)을 남길 수 있는 웹앱입니다. 빌드 과정 없이 `index.html` 하나로 동작하며, GitHub Pages 등 정적 호스팅에 바로 올릴 수 있습니다.

## 주요 기능

- **명단관리**: 학생 추가/수정/삭제, 여러 명 붙여넣기로 일괄 등록, 엑셀(.xlsx) 파일이나 구글 스프레드시트에서 명단·MBTI·선호역할·지식점수 등을 한 번에 가져오기. 시트가 여러 개(반별 시트 등)면 하나씩 골라 가져올 수 있습니다.
- **모둠배정**: 모둠 수 또는 모둠당 인원 수를 지정해 무작위 배정, 학생을 클릭(또는 드래그)해서 원하는 모둠으로 자유롭게 재배정, 회차별로 저장/조회. 이미 저장한 회차도 "수정"으로 다시 열어 구성원을 바꿀 수 있습니다. 각 모둠은 색으로 구분된 카드에 학생 칩이 모여 보이도록 표시됩니다.
- **모둠기록**: 회차·모둠별로 활동 내용과 관찰 기록을 날짜와 함께 작성
- **개인기록**: 학생별로 자율활동/동아리활동/진로활동/봉사활동/행동특성 및 종합의견/교과학습발달상황 등 구분에 맞춰 기록을 남기고, 생기부 작성용 텍스트로 내보내기
- **여러 기기 동기화**: Firebase(Firestore)를 연결하면 같은 "학급 코드"를 사용하는 PC·태블릿·휴대폰에서 실시간으로 데이터가 동기화됩니다. 연결하지 않아도 브라우저 로컬 저장소에 자동 저장되어 계속 사용할 수 있습니다.
- **구글 스프레드시트 연동**: 명단/모둠배정/모둠기록/개인기록을 스프레드시트 4개 탭으로 내보내거나, 기존 스프레드시트에서 명단을 불러올 수 있습니다.

## 처음 사용하기 (설정 없이)

`index.html`을 웹서버에 올리거나 로컬에서 바로 열면, 별도 설정 없이도 이 브라우저(이 기기)에 데이터가 저장되며 모든 기능(명단/배정/기록)을 사용할 수 있습니다. 여러 기기에서 함께 쓰려면 아래 Firebase 설정이 필요합니다.

## 여러 기기 동기화 설정 (Firebase)

1. [Firebase 콘솔](https://console.firebase.google.com/)에서 새 프로젝트를 만듭니다.
2. **Firestore Database**를 생성합니다 (프로덕션 모드 권장).
3. **Firestore 규칙**을 아래와 같이 설정해, 로그인(익명 포함)한 사용자만 접근하도록 합니다.
   ```
   rules_version = '2';
   service cloud.firestore {
     match /databases/{database}/documents {
       match /classes/{classId} {
         allow read, write: if request.auth != null;
       }
     }
   }
   ```
4. **Authentication → Sign-in method**에서 "익명(Anonymous)" 로그인을 사용 설정합니다.
5. 프로젝트 설정 → "내 앱"에서 웹 앱을 추가하고, 표시되는 설정 객체(JSON)를 복사합니다.
6. 앱의 **설정** 탭에 붙여넣고 "적용"을 누릅니다.
7. 상단의 "학급 코드"를 다른 기기와 동일하게 입력하면 같은 데이터가 실시간으로 공유됩니다. (학급 코드는 비밀번호 역할을 겸하므로 외부에 공개되지 않도록 주의하세요.)

## 구글 스프레드시트 연동 설정

1. [Google Cloud Console](https://console.cloud.google.com/)에서 프로젝트를 만들거나 선택합니다.
2. **API 및 서비스 → 라이브러리**에서 "Google Sheets API"를 사용 설정합니다.
3. **API 및 서비스 → OAuth 동의 화면**을 구성합니다 (테스트 단계에서는 본인 계정을 테스트 사용자로 추가).
4. **사용자 인증 정보 → OAuth 클라이언트 ID 만들기 → 웹 애플리케이션**을 선택하고, "승인된 자바스크립트 원본"에 앱을 호스팅할 주소(예: `https://username.github.io`, 로컬 테스트 시 `http://localhost:포트`)를 추가합니다.
5. 생성된 클라이언트 ID를 앱의 **설정** 탭에 입력합니다.
6. "Google 계정 연결"로 로그인한 뒤, 명단관리 탭에서 스프레드시트 URL/ID와 범위(예: `시트1!A1:D100`)를 입력해 명단을 가져오거나, 설정 탭에서 전체 데이터를 새 스프레드시트로 내보낼 수 있습니다.

`spreadsheets` 범위는 민감 범위로 분류되어 있어, 앱을 검증받지 않은 상태에서는 OAuth 동의 화면에 등록된 테스트 사용자 계정으로만 로그인할 수 있습니다. 학교 내 소규모 사용에는 테스트 사용자 등록만으로 충분합니다.

## 배포

빌드 과정이 없으므로 `index.html`을 GitHub Pages, Netlify 등 아무 정적 호스팅에 올리면 바로 동작합니다. GitHub Pages를 쓴다면 저장소 설정 → Pages에서 배포할 브랜치를 지정하세요.

## 데이터 백업

Firebase나 구글 계정 없이도 설정 탭의 "백업 파일 저장/불러오기"로 전체 데이터를 JSON 파일로 내려받거나 복원할 수 있습니다.
